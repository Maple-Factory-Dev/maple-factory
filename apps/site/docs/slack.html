Slack

Ask @Maple in Slack.

Mention @Maple in a channel and it answers from your code. When the thread is really asking for a change, its answer comes with a proposed task: click Create task, and it’s in the factory, planning.

What it does

  • Mention @Maple in a thread with a question. It says Looking into it…, and an agent on one of your factory’s online machines reads the code of the channel’s best-suited goal and answers in the thread. That agent can only read: it can’t change files, push or open pull requests.
  • If the thread asks for a change or describes a bug, the answer also shows a proposed task: its goal, its title and what should be true when it’s done, with Create task and Not now.
  • Create task makes the task in that goal and sends it to planning. A member still approves the plan before anything is built. One click makes one task; a second click says it’s already made. Proposals expire after 30 minutes; mention Maple again for a fresh one.
  • The thread becomes a request in the factory. It hears when a planner starts, when the plan is ready for approval, questions from the task’s agent, and when the change merges.
  • /maple <what you need> still works too: it files a request for someone to pick up, without an agent answering.

Set it up

An admin does this once, from the web app’s Settings › Integrations. Your factory needs its public URL (PUBLIC_URL) set, since Slack has to reach it.

  1. Create the Slack app

    On the Slack card, click Create the Slack app. Slack opens with an app manifest that already names your factory’s events, interactivity and slash command URLs. Pick your workspace and create it.

  2. Install it to your workspace

    In the new app, open Install App and click Install to Workspace. A workspace admin may need to approve it.

  3. Paste two values

    From the app, copy Basic Information › Signing Secret and OAuth & Permissions › Bot User OAuth Token (it starts with xoxb-) into the Slack card, and save. Both are stored sealed in your factory and never shown again.

Then invite it to a channel, public or private: /invite @Maple. In a private channel it only sees what happens after it’s invited. Without the bot token, only /maple works.

Made your Slack app from an older manifest? If its OAuth & Permissions › Bot Token Scopes don’t list groups:history, it’s missing scopes Maple now needs: add channels:read, groups:read, mpim:read and groups:history, then reinstall it from Install App (or delete it and click Create the Slack app again). Reinstalling keeps the same bot token; if it changes, paste the new one into the Slack card.

Scopes, and why

  • app_mentions:read: to hear when someone mentions @Maple.
  • chat:write: to answer in the thread, and to update its own answer when a button is clicked.
  • channels:history: to read the thread it was mentioned in, so the agent has the whole conversation. It reads only that thread, when it’s mentioned.
  • groups:history: the same, in a private channel it’s been invited to.
  • channels:read, groups:read and mpim:read: Slack requires these to tell Maple when it joins a channel, so it can ask which goals to work on there.
  • files:read: to fetch files posted in that thread, so they can go into the task.
  • users:read: to name who asked, in the request and the task.
  • commands: for /maple.

Every request from Slack is checked against the app’s signing secret and refused if it’s more than five minutes old; Slack’s retries of an event are taken once.

Channels and goals

  • When Maple joins a channel, it asks Which goals should I work on here? Pick one or more goals, or Any goal. It answers from the best-suited of those goals’ code and proposes tasks only in them.
  • Mention @Maple goals to bring the picker back and choose again.
  • Archived goals drop out on their own. If every goal a channel picked is archived, Maple works across all active goals and says once that the channel should pick again.

Files

  • Files posted in the thread (screenshots, logs, PDFs; up to 10, 25 MB each) are fetched with the bot token and stored in your factory’s R2 bucket, like attachments pasted into a brief.
  • The agent answering is told their names. When a task is made, its brief links each one under Attachments, and the machine building it fetches them with its own token.

Limits

  • It needs a machine online: answers come from an agent on one of your runners (Claude Code, or Codex). With none online, Maple says so in the thread.
  • Direct messages aren’t supported yet. In a private channel, Maple has to be invited with /invite @Maple first.
  • A task made from Slack belongs to whoever owns the machine that answered, and is open to team slots.
