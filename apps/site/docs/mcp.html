MCP

Your docs, in Claude and Cursor.

Your factory runs a remote MCP server. Connect Claude Desktop, claude.ai, Claude Code or Cursor to it, and they can read your planning docs, comment on them, suggest edits and propose decisions, as you. A person still accepts every edit and decides every decision.

The endpoint

It’s https://YOUR-FACTORY/mcp, over MCP’s streamable HTTP transport, with YOUR-FACTORY replaced by your factory’s host. The web app’s Settings › Connected apps shows the exact URL to copy. Every member can connect, not only admins.

What it can and can’t do

  • It can list your factory’s docs and read one, with its block ids and open threads.
  • It can comment on a doc, reply to a thread, resolve a thread, suggest an edit and propose a decision.
  • It never edits a doc’s text. A suggested edit waits for a person to accept it, and a proposed decision waits for a person to decide it.
  • Everything it writes shows as you, with a <client> via MCP badge (like Claude via MCP), so everyone can tell it came from an agent.
  • With the tasks scopes, it can search your factory’s goals and tasks and read one: its brief, plan, done-when items and comments.
  • It can propose tasks in a goal. Each is a draft owned by you that a person sends to planning or deletes; nothing plans or builds until they do.
  • It can comment on a task as you. It can’t approve a plan, ask for changes, merge or cancel.
  • It sees only docs, goals and tasks: not code, session logs, costs, secrets or settings.
  • Try: “Find the task about rate limits in Maple Factory and tell me where it’s at”, or “Propose a task in Maple Factory to rate-limit /mcp per token.”

Scopes

  • docs:read: list_docs and read_doc.
  • docs:write: comment_on_doc, reply_to_doc_thread, resolve_doc_thread, suggest_doc_edit and propose_decision.
  • tasks:read: list_goals, list_tasks and get_task. Both lists search with q; list_tasks also filters by goal, state, owner, priority and effort.
  • tasks:write: propose_tasks (drafts only) and comment_on_task.

A client gets only the tools its scopes allow. Give it docs:write or tasks:write only if you want it writing as you. A token made before the tasks scopes existed keeps only its docs scopes.

Claude Desktop and claude.ai

  1. Add a custom connector

    In Claude Desktop or claude.ai, open Settings › Connectors › Add custom connector, name it Maple and paste your factory’s /mcp URL.

  2. Approve it in your factory

    Claude opens your factory’s consent page. Sign in with GitHub if you aren’t already, check which scopes it asks for, and approve. It shows up in Settings › Connected apps as an OAuth client.

This is OAuth 2.1: the authorization code flow with PKCE (S256) and dynamic client registration, so there’s nothing to paste but the URL. Access tokens last an hour and the client refreshes them on its own; each refresh replaces the old pair. A refresh token goes unused for 30 days and the connector has to be approved again.

Claude Code

Make a personal token in Settings › Connected apps › New personal token. It’s shown once, starting mfp_, with this command filled in:

claude mcp add --transport http maple https://YOUR-FACTORY/mcp --header "Authorization: Bearer mfp_…"

Cursor

With a personal token, add this to ~/.cursor/mcp.json (or a project’s .cursor/mcp.json):

{
  "mcpServers": {
    "maple": {
      "url": "https://YOUR-FACTORY/mcp",
      "headers": {
        "Authorization": "Bearer mfp_…"
      }
    }
  }
}

Any other client that speaks streamable HTTP and can send a header works the same way.

Revoking

  • Your OAuth clients and personal tokens are listed in Settings › Connected apps, with their scopes, when they were made and when they were last used. Revoke stops one at once.
  • When an admin removes a member’s access in Settings › People, all of that member’s MCP tokens stop working too.

Security

  • Tokens are stored hashed (SHA-256); the factory can’t show one again after it’s made.
  • MCP tokens work only at /mcp. They can’t sign in to the web app or call its API, and they can’t manage tokens.
  • The apps’ own tokens (the Mac and phone apps’) don’t work at /mcp.
  • Issuing and revoking a token are recorded in the factory’s audit log. See Security for the rest.
